# Архитектура доступности

Версия 0.3 (ЭТАП 0, сверено с ТЗ и аудитом), 2026-11-09. Цель: **WCAG 2.2 уровень AA** — целевой ориентир ТЗ (§7.4, с. 17) и бриф (Б§16). Других национальных норм доступности ТЗ не называет.

**Что требует ТЗ §7.4, с. 17** (обязательный минимум): контрастный текст, навигация с клавиатуры, альтернативные описания изображений, понятные подписи кнопок, читаемые шрифты, логичная структура заголовков, корректная работа экранных дикторов, увеличение масштаба, отсутствие зависимости только от цвета. Кроме того: контраст в обеих темах (§5.10, с. 12), полноценная мобильная версия (§7.1, с. 16), Lighthouse ≥ 80 по доступности (§7.2, с. 16), корректное отображение на трёх языках (§9, с. 20).

**Что добавляет бриф** (решение команды сверх ТЗ): панель настроек доступности, режимы движения, когнитивная доступность, доступный просмотрщик сканов, требования к медиа, размер целей 44×44. Эти пункты помечены в матрице как `Б`.

Доступность здесь — свойство основного интерфейса. Отдельной «версии для слабовидящих» нет: панель настроек меняет параметры того же интерфейса и ничего не скрывает.

## 0. Нарушения текущего сайта, которые не повторяем

Аудит e-arhiv.vko.gov.kz (9.11.2026, `source/site-audit/accessibility-audit.md`) подтвердил на главной нарушения WCAG 2.2 AA. Для каждого есть автоматическая проверка в новом проекте:

| Нарушение текущего сайта | Критерий | Проверка в новом проекте |
|---|---|---|
| Ширина документа 1052 px на 320–768 px, поиск за краем экрана | 1.4.10 | Playwright: `scrollWidth ≤ clientWidth` на 10 ширинах; поиск в видимой области на 360 px |
| Ссылка новости `#BA9937` на `#FBF8EF` — 2,57:1 | 1.4.3 | Скрипт контраста токенов, включая hover и active |
| Пустой `lang` у `<html>` | 3.1.1 | axe `html-has-lang`, `html-lang-valid` |
| Оргструктура картинкой с `alt=""`, без текста | 1.1.1 | Схемы публикуются только с текстовым эквивалентом (список подразделений); админка требует alt или текст |
| Поле и кнопка поиска без доступных имён | 4.1.2 | axe `label`, `button-name` |
| Безымянные ссылки-миниатюры и баннеры | 2.4.4 | Карточка — одна ссылка с именем; axe `link-name` |
| Нет `main`, `nav`; даты новостей в `h2` | 1.3.1, 2.4.1 | Каркас с landmarks; e2e проверяет landmarks и порядок заголовков |
| Меню филиалов не получает фокус | 2.1.1 | e2e-сценарий 16 проходит меню и переключатели |
| Каталог зависает на `Loading…` без сообщения | 4.1.3, 3.3.1 | Состояния загрузки, пустого ответа и ошибки с `aria-live` и кнопкой «Повторить» |
| Повторяющиеся ID в опросе | 4.1.1 / 1.3.1 | axe `duplicate-id-aria`; опросов на новом сайте нет |
| Ссылка на внешний инструмент «для слабовидящих» вместо доступного интерфейса | — | Собственная панель настроек §5, без сторонних скриптов |

## 1. Принципы (POUR) в виде инженерных правил

| Принцип | Правило проекта |
|---|---|
| Воспринимаемость | Весь смысл есть в тексте; изображения со смыслом имеют alt; медиа имеют субтитры и расшифровки; контраст AA в обеих темах |
| Управляемость | Всё доступно с клавиатуры; нет ловушек фокуса; фокус всегда видим и не перекрыт; цели ≥ 24×24, стремимся к 44×44; нет обязательного перетаскивания и точных жестов |
| Понятность | Простые слова; одинаковые действия называются одинаково; ошибки объясняют, как исправить; язык страницы и фрагментов размечен |
| Совместимость | Нативные элементы и Radix-примитивы с правильными ролями; ARIA только там, где нет нативной семантики |

## 2. Дизайн-токены и контраст

- Цвета задаются парами «фон/текст», каждая пара проверяется скриптом в CI (порог 4.5:1 для текста, 3:1 для крупного текста, границ полей и иконок, 3:1 для индикатора фокуса).
- Наборы токенов: `light`, `dark`, `high-contrast-light`, `high-contrast-dark`, `alt-scheme` (тёплая низкоконтрастная к белому фону схема, например кремовый фон и тёмно-коричневый текст, для людей, которым мешает яркий белый; контраст по-прежнему ≥ 4.5:1).
- Тёмная тема без чистого чёрного: фон в диапазоне `#121417`–`#1b1d21`, текст не чистый белый.
- Размеры в `rem`; базовый кегль 16 px (18 px для длинного чтения); межстрочный 1.5 для текста.
- Индикатор фокуса: обводка 3 px с отступом 2 px, цвет с контрастом ≥ 3:1 к обоим соседним цветам; единый стиль для всех элементов через `:focus-visible`.

## 3. Семантика и структура страницы

- Каркас: `SkipLink` («Перейти к основному содержимому», первый фокусируемый элемент) → `header` (`banner`) → `nav aria-label` (основная навигация) → `main id="main"` → `footer` (`contentinfo`).
- Ровно один `h1`, без пропуска уровней.
- Списки результатов — `ol`/`ul`; таблица только для табличных данных (например, состав дела), с `caption` и `th scope`.
- При смене маршрута SPA: обновляется `<title>`, фокус переводится на `h1` новой страницы (с `tabindex="-1"`), диктору объявляется заголовок.
- Хлебные крошки: `nav aria-label="Хлебные крошки"`, текущая страница с `aria-current="page"`.
- Иконки декоративные (`aria-hidden`), у кнопок-иконок `aria-label` из i18n.

## 4. Компоненты и клавиатура

Основа — shadcn/ui на Radix, которые реализуют паттерны ARIA APG. Для каждого компонента в дизайн-системе фиксируется ожидаемое поведение:

| Компонент | Клавиши | Примечания |
|---|---|---|
| Кнопка, ссылка | Enter (ссылка), Enter/Space (кнопка) | Ссылки ведут, кнопки действуют; не путать |
| Диалог | Esc закрывает; Tab циклически внутри; фокус возвращается на вызвавший элемент | Используется для фильтров на мобильных и подтверждений |
| Меню, выпадающий список | Стрелки, Home/End, Esc | |
| Табы | Стрелки между вкладками, Tab в содержимое | |
| Раскрывающиеся блоки (FAQ) | Enter/Space | `button aria-expanded` |
| Пагинация | Tab | `nav aria-label`, текущая страница `aria-current="page"` |
| Слайдер настроек | Стрелки, Home/End | Дублируется кнопками «−»/«+» |
| Просмотрщик | см. §9 | |
| Карта | см. §10 | |

Форма:
- У каждого поля видимая подпись (`label`), подсказки связаны `aria-describedby`.
- Ошибки: текст + иконка рядом с полем, сводка ошибок вверху формы со ссылками на поля; фокус переводится на сводку; введённые данные сохраняются.
- Админка (ТЗ §9, с. 20: единый стиль) подчиняется тем же правилам. Порядок экспонатов и страниц меняется кнопками «Выше/Ниже» и полем номера, перетаскивание — только дополнительный способ (WCAG 2.5.7).
- Форма отзывов: без капчи-картинки; защита от спама через honeypot и rate limit, чтобы не создавать барьер для незрячих пользователей.
- Обязательность обозначена словом, а не только звёздочкой.
- `autocomplete` для полей входа.

Динамика:
- Количество результатов поиска объявляется через `aria-live="polite"` после завершения загрузки, без объявления на каждое нажатие клавиши.
- Уведомления (toast) не исчезают раньше, чем пользователь их прочитает: важные ошибки показываются в странице, а не только во всплывающем сообщении.
- Нет звуковых уведомлений.

## 5. Панель настроек доступности

Доступна из шапки на каждой странице (кнопка с текстом «Доступность» и иконкой), а также на странице `/accessibility` с инструкциями.

| Настройка | Значения | Реализация |
|---|---|---|
| Размер текста | 100, 125, 150, 175, 200 % | `font-size` на `html` (все размеры в rem); не конфликтует с масштабом браузера, потому что тот масштабирует поверх |
| Межстрочный интервал | стандартный, 1.8, 2.0 | CSS-переменная `--a11y-line-height` |
| Межбуквенный интервал | стандартный, 0.12em, 0.16em | `--a11y-letter-spacing` (+ word-spacing 0.16em по WCAG 1.4.12) |
| Повышенная контрастность | вкл/выкл | набор токенов `high-contrast-*` |
| Цветовая схема | светлая, тёмная, системная, альтернативная | отдельно от контраста: настройки независимы |
| Шрифт | стандартный, шрифт с повышенной различимостью (например, Atkinson Hyperlegible — проверить поддержку казахской кириллицы) | `--a11y-font` |
| Уменьшение анимации | системное, вкл, выкл | атрибут `data-motion="reduce"` |
| Упрощённый режим | вкл/выкл | меньше декоративных блоков, нет параллакса и фоновых изображений, одна колонка контента, крупнее ссылки. Весь контент остаётся доступным |
| Сброс | кнопка | возврат к значениям по умолчанию с подтверждением в `aria-live` |

Технически:
- Настройки — React-контекст + атрибуты `data-*` и CSS-переменные на `<html>`. Применяются до первой отрисовки инлайн-скриптом в `index.html`, чтобы не было вспышки.
- Хранение только в `localStorage` (Q-16). Без cookie и без передачи на сервер.
- Панель — немодальная боковая панель (Radix Dialog), полностью управляется клавиатурой, сама проходит те же проверки, что и сайт.
- Изменения применяются сразу; каждая настройка имеет понятную подпись и пример текста.
- Проверка: при 200 % тексте и 0.16em интервалах ни один элемент не обрезается (WCAG 1.4.12) на 320 px.

## 6. Когнитивная доступность

- Словарь интерфейса (`docs/accessibility/ui-glossary.md`): одно понятие — одно слово на каждом языке («Фонд», «Опись», «Дело» с пояснением при первом появлении через `abbr`/подсказку и ссылку в глоссарий).
- Пустые состояния говорят, что сделать дальше («Ничего не найдено. Попробуйте убрать фильтр „Год“ или поискать по номеру фонда»).
- Нет автообновления контента, каруселей с автопрокруткой, всплывающих окон без действия пользователя.
- Пагинация вместо бесконечной прокрутки; позиция и фильтры сохраняются при возврате назад.
- Длинные тексты: подзаголовки, оглавление для публикаций длиннее ~1500 слов, ширина строки ≤ 75 символов.
- Расположение шапки, поиска и навигации одинаково на всех страницах (WCAG 3.2.3, 3.2.6 — помощь в одном месте).
- Никаких таймаутов на публичной части; в админке предупреждение об истечении сессии с возможностью продлить.

## 7. Движение

- По умолчанию учитывается `prefers-reduced-motion`; пользователь может переопределить в панели.
- В режиме `reduce`: отключаются переходы, параллакс, плавная прокрутка; остаются мгновенные смены состояния.
- Нет мигания чаще 3 раз в секунду, нет автозапуска видео; видео стартует только по действию пользователя и без звука по умолчанию.
- Любое автоматическое движение (если появится) имеет кнопку «Пауза».

## 8. Медиа

- Видео публикуется только с субтитрами (WebVTT) на языке оригинала; расшифровка текстом рядом. Админка не даёт опубликовать видео без субтитров (A-008).
- Аудио — с текстовой расшифровкой.
- Плеер — нативный `<video controls>` с дорожкой субтитров; без собственных контролов, пока нативные удовлетворяют требованиям.

## 9. Просмотрщик архивных сканов

| Функция | Мышь/касание | Клавиатура | Кнопки |
|---|---|---|---|
| Масштаб | колесо (с Ctrl), щипок | `+` / `−`, `0` — сброс | «Увеличить», «Уменьшить», «По размеру экрана» |
| Перемещение | перетаскивание | стрелки | 4 кнопки направления (видимы при масштабе > 1) |
| Страницы | миниатюры | PageUp/PageDown | «Предыдущая», «Следующая», поле «Страница N из M» |
| Полноэкранный режим | — | `F`, Esc для выхода | кнопка |
| Поворот | — | `R` | кнопка |

- Горячие клавиши работают только при фокусе на просмотрщике и перечислены в справке; одиночные символьные сочетания можно отключить (WCAG 2.1.4).
- Рядом со сканом всегда: метаданные текстом, описание изображения (`long_description`), расшифровка, если есть.
- Если текстового слоя и расшифровки нет, это прямо сообщается: «Текстовая расшифровка этой страницы отсутствует». Мы не заявляем, что скан читается экранным диктором (A-014).
- Смена страницы объявляется через `aria-live`: «Страница 3 из 12».
- Большие сканы отдаются тайлами (DZI) или прогрессивными производными; при необходимости используется OpenSeadragon с собственными доступными кнопками.

## 10. Карта

- Карта — дополнение к списку филиалов, а не замена (F-066). Список отрисовывается всегда и стоит в DOM до карты.
- Расстояние до филиала (ТЗ §5.5, с. 8) показывается текстом в списке и в карточке, с подписью «по прямой».
- Ссылки на маршрут в Google Maps и 2GIS открываются в новой вкладке с текстовым предупреждением об этом.
- Карта имеет доступное имя, кнопки масштаба Leaflet с переведёнными подписями, маркеры фокусируемы и открывают ту же карточку, что и элемент списка.
- Выбор в списке подсвечивает маркер (текстом и формой, не только цветом), и наоборот.
- Есть ссылка «Пропустить карту».
- Геолокация только по нажатию кнопки, с объяснением, зачем она; отказ сообщается текстом, страница работает дальше.

## 11. Адаптивность

- Mobile-first; контрольные ширины 320, 360, 375, 390, 430, 768, 1024, 1280, 1440, 1920.
- На 320 px: нет горизонтальной прокрутки (кроме просмотрщика и широких таблиц внутри собственного контейнера с подписью), фильтры каталога открываются в полноэкранном диалоге, навигация в меню-диалоге.
- Ориентация экрана не фиксирована.
- Поддержка 400 % масштаба для reflow (1.4.10).

## 12. Проверки и процесс

| Проверка | Инструмент | Когда |
|---|---|---|
| Автоматическая | `@axe-core/playwright` во всех e2e-сценариях | Каждый прогон тестов |
| Компонентная | `vitest-axe` для компонентов дизайн-системы | Каждый прогон |
| Lint | `eslint-plugin-jsx-a11y` | При сборке |
| Контраст токенов | собственный скрипт по парам токенов | CI |

| Lighthouse | Lighthouse CI на prod-сборке | Этапы 4, 14 |
| WAVE | расширение браузера (если доступно) | Этап 14 |
| Клавиатура | ручной чек-лист по сценариям U1–U10 | Каждая фича |
| Экранный диктор | NVDA + Firefox/Chrome (Windows), VoiceOver + Safari (macOS, iOS) | Этапы 6, 14 |
| Масштаб 200/400 %, интервалы 1.4.12 | вручную | Каждая фича |
| Темы, высокий контраст, reduced motion | вручную + скриншоты Playwright | Каждая фича |
| Цветовое восприятие | эмуляция в DevTools (протанопия, дейтеранопия, тританопия, ахроматопсия) | Этапы 3, 14 |

Результаты пишутся в `docs/accessibility/audit-log.md`: дата, что проверено, найденное нарушение с критерием WCAG, решение, статус. Автоматические проверки не заменяют ручные; высокий балл Lighthouse не считается доказательством соответствия.

Ограничения, которые нужно честно указывать в заявлении о доступности (`/accessibility`): сканы без расшифровки, сторонние внешние сервисы маршрутов, исторические материалы с низким качеством изображения.

**ИИ-помощник** (ТЗ §5.8, с. 10; §7.1, с. 16): чат — область `role=log` с `aria-live="polite"`, поле ввода с подписью, ответ объявляется после завершения генерации (не по токенам), ссылки-источники — обычный список ссылок. Виджет не перекрывает контент на мобильных и закрывается по Esc.


## 13. Состояние реализации (ЭТАП 3, 2026-11-09)

- Каркас `frontend/`: SkipLink → `header` → `nav` → `main#main` → `footer`; один `h1` на странице, `<title>` и фокус на `h1` при смене маршрута; `lang` у `<html>` по префиксу адреса, у ссылок языка — собственный `lang` и `hreflang`.
- Токены: `frontend/src/styles/tokens.css`, 5 тем (`light`, `dark`, `alt`, высокий контраст светлый и тёмный). Контраст проверяет `frontend/tests/contrast.test.ts`.
- Панель: `frontend/src/components/accessibility/A11yPanel.tsx`, нативные радиокнопки и флажки. Настройки применяются до отрисовки инлайн-скриптом `index.html`; совпадение с `applyPrefs` проверяется тестом.
- Шрифт повышенной различимости — системные Verdana/Tahoma/DejaVu Sans/Noto Sans без загрузки веб-шрифтов (самостоятельное размещение, без внешних CDN). Atkinson Hyperlegible не используется: поддержка казахских букв не подтверждена.
- Результаты проверок — `docs/accessibility/audit-log.md`.
