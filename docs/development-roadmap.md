# План разработки

Версия 0.3 (ЭТАП 0, сверено с ТЗ и аудитом текущего сайта), 2026-11-09. Исполнитель: один разработчик. **Защита: 13 ноября 2026** (рекомендации организаторов). Структура этапов и объём P0 сохранены по решению пользователя; документация и модель данных приведены к ТЗ.

## 1. Стратегия

Приоритет — завершённые сквозные сценарии, а не количество страниц. Первым строится «вертикальный срез»: каталог → карточка → просмотрщик → админка документа → согласование и публикация, на трёх языках, с доступностью и темами. Остальные разделы повторяют отлаженные шаблоны.

ТЗ §9, с. 20 рекомендует подготовить пять экранов: главная, каталог, карточка документа, онлайн-выставка, админ-панель. Четыре из них входят в P0, выставка — первая в очереди P1.

Отступления от порядка этапов брифа (Б§26), с причинами:

| Отступление | Причина |
|---|---|
| Каркас i18n и языковые префиксы — на ЭТАПЕ 2–3, а не 11 | Иначе придётся переписывать все строки и маршруты. На ЭТАПЕ 11 остаётся заполнение и вычитка переводов |
| Базовая безопасность (сессии, тайм-аут, RBAC, CSRF, ограничение входа, валидация, аудит) — на ЭТАПЕ 2 и 10, а не 13 | Админка без серверной проверки прав — критическая ошибка; ЭТАП 13 становится аудитом и усилением |
| Минимальная админка документов — сразу после каталога | Без неё нельзя показать сценарии 9–12 и согласование публикаций |
| Тесты пишутся в каждом этапе | ЭТАП 14 — сводный прогон и оптимизация |

## 2. Обязательное для хакатона и перспективное

### P0 — без этого демонстрация не имеет смысла
Состав P0 не изменился. Внутри тех же пунктов учтены уточнения ТЗ (отмечены «ТЗ»).

- Инфраструктура: Docker Compose (Postgres, MinIO, backend, frontend, Nginx), миграции, сиды demo/synthetic, а также реальные справочные данные текущего сайта (площадки, филиалы, контакты) с пометкой «требует сверки».
- Дизайн-система, тёмная/светлая тема, панель доступности, каркас страниц. **ТЗ:** шапка из 7 элементов (§4, с. 3–4) и подвал из 7 элементов (§5.1, с. 4).
- i18n KZ/RU/EN для интерфейса и карточек документов; переводы редактируются в админке (§5.9, с. 12).
- Главная (баннер, поиск, переходы). **ТЗ:** блок «История в документах» (§5.1, с. 4). **Аудит:** переходы оформлены как четыре прямых входа на первом экране (F-019) — это те же ссылки баннера, не новый блок.
- Поиск в шапке отделён от поиска по каталогу (F-007, аудит Р3) — внутри уже запланированных поиска и каталога.
- Каталог: поиск, фильтры, сортировка, пагинация, URL-состояние, все состояния. **ТЗ:** категории каталога (§5.3, с. 5).
- Карточка документа + доступный просмотрщик. **ТЗ:** карточка документа с ограниченным доступом с условиями доступа, без копии (§5.3, с. 6) — это вариант той же карточки.
- Админка: вход, CRUD фондов/описей/дел/документов, загрузка файлов, публикация, аудит, роли. **ТЗ:** публикация идёт через статусы согласования (§6.7, с. 15) — та же функция «публикация», но с 6 статусами вместо 2; автоматический выход по неактивности и ограничение попыток входа (§7.3, с. 16).
- Закрытые материалы недоступны (API + файлы).
- e2e-сценарии 1–5, 9–13, 16 (для P0-страниц), 18; axe во всех.

### P1 — нужно для полноты
- Онлайн-выставки (экран, рекомендованный ТЗ §9).
- Филиалы: список + карта + маршруты Google Maps/2GIS + расстояние по прямой + геолокация по кнопке (§5.5).
- Отзывы и предложения (разрешены организаторами).
- ИИ-помощник «поиск + ссылки» и интеллектуальный поиск с разбором запроса (§5.8 А, Б) — в ТЗ это ключевая возможность, поэтому поднят из P2 в P1.
- Архив памяти: публикации, коллекции, персоналии, хронология, галерея (§5.6).
- Новости (§5.11), Об архиве (§5.2), Справка (§5.4) с отдельными страницами «Посетить читальный зал» и «Как получить архивную справку» (только информация, аудит Р1, Р5), FAQ, соцсети (§5.12).
- Реестр филиалов с компетенцией и зоной обслуживания (аудит Р7); реестр миграции и сиды `migrated` (§11, аудит Р9).
- Импорт CSV/Excel и экспорт (§6.3), настройка прав ролей (§6.1), филиалы в админке (§6.4).
- SEO: мета-рендер, JSON-LD, sitemap, robots (§7.5).
- e2e-сценарии 6–8, 14, 15, 17.

### P2 — если останется время
- Генерация ответов помощника локальной LLM поверх поиска; ИИ по историческим материалам (§5.8 В).
- Отчёт качества сайта по журналу запросов (§5.8 Д), dashboard.
- OCR и поиск дубликатов для сотрудников (§5.8 Г).
- WebP/AVIF, DZI-тайлы, ClamAV, скрипты бэкапа, меню из админки.

### Перспектива (после хакатона)
- Личный кабинет и избранное (§8.1), историческая карта региона (§8.3), лента соцсетей через API (§5.12).
- Семантический поиск pgvector с гибридным ранжированием, рекомендательная система (§8.4).
- Импорт из системы учёта заказчика и полная миграция текущего сайта (§11).
- Собственный тайл-сервер, TOTP, восстановление пароля, WAL-архивирование, мониторинг, Umami.
- Развёртывание в ЦОД РК, нагрузочное тестирование, внешний аудит доступности и безопасности.

## 3. Этапы и календарь

Оценки — рабочие дни одного человека в обычном темпе, как в версии 0.1. **Сумма P0 ≈ 15 дней, а до защиты 3,5 календарных дня.** План выполним только при ускоренном темпе с генерацией кода и при строгом соблюдении порядка: каждый день заканчивается работающей демонстрацией, чтобы при нехватке времени показать то, что уже готово. ## 4. Порядок работы внутри этапа

Каждая итерация (Б§24): структура → `tsc --noEmit` → сборка → тесты → исправления → проверка затронутых страниц → адаптивность (10 ширин) → доступность (axe + клавиатура) → документация → матрица требований. Статус в матрице меняется только по факту проверки. Отчёт по формату Б§25.

## 5. Тестовая стратегия

| Уровень | Инструмент | Что покрывает |
|---|---|---|
| Unit | Vitest | Разбор шифра, сборка фильтров, переходы статусов согласования, права, санитизация, даты |
| Компоненты | Vitest + RTL + vitest-axe | Компоненты дизайн-системы, формы, состояния |
| API | Vitest + `fastify.inject` на тестовой БД (Docker) | Каждый эндпоинт: валидация, права, публичный фильтр, `restricted` без файлов |
| e2e | Playwright + `@axe-core/playwright` | 18 сценариев Б§22 + цикл согласования (ТЗ §6.7), мобильные проекты, 10 ширин |
| Ручные | чек-листы | Экранные дикторы, масштаб, цветовое восприятие |
| Lighthouse | Lighthouse CI | ≥ 80 по производительности и доступности (ТЗ §7.2, с. 16) |

Соответствие 18 сценариев брифа: 1→U1, 2→U2, 3→U3, 4–5→U4, 6→U5, 7→U6, 8→U7, 9–11→U8, 12 и 18→U9, 13–15→U10, 16–17→U11. Дополнительно: U14 (restricted), U15 (согласование).

## 6. Риски

| Риск | Влияние | Мера |
|---|---|---|
| 3,5 дня на P0 при оценке 15 дней | Не все P0-пункты будут полными | Колонка «Минимум»; рабочая демонстрация в конце каждого дня; контрольная точка 12.11 |
| ТЗ шире P0 (около 175 требований) | На защите спросят про не сделанное | Матрица показывает статус и план по каждому требованию; архитектура и модель данных покрывают всё ТЗ |
| Нет реальных данных | Демо выглядит искусственно | Реестр контента из аудита; перенос справочных данных с пометкой `migrated` и «требует сверки»; демо-записи с плашкой |
| Реквизиты текущего сайта противоречивы (индексы, годы отчётов) | Ошибка в официальных данных на защите | Несверенные данные помечены; ничего не выдаём за подтверждённое |
| Качество локальной LLM на казахском | Слабые ответы | Помощник и интеллектуальный поиск работают на правилах и словарях; LLM — улучшение |
| Тайлы OSM на демонстрации | Политика использования | Малая нагрузка, атрибуция, кэш Nginx |
